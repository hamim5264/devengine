Studio events run on Firebase Cloud Functions (Node 22). From this folder install dependencies with `npm install`, then from the repository root deploy using `firebase deploy --only functions,firestore --project dev-engine-aec69 --account hamim.leon@gmail.com` after reviewing the changes. A Firebase project with Cloud Functions billing enabled is required.

The browser never creates notifications. Firestore triggers deliver persistent, deduplicated notifications for messages, broadcasts, memberships, employee account/access changes, attendance, requests, tasks, work updates and agreements, including changes made outside these new screens. Existing employee profiles are safely backfilled when the administrator opens the portal. Only names, avatars, role, account/chat status and department IDs are exposed through the directory; credentials remain private.

Full account suspension immediately denies portal data through Firestore rules and the existing live session guard. The employee-directory trigger also disables Firebase Authentication sign-in and revokes refresh tokens; restoring the account enables sign-in again. Chat-only suspension leaves Authentication untouched. Employee identities are preserved. Message attachments are intentionally unavailable.

The conversation membership index is included in `firestore.indexes.json`. Wait until Firebase finishes building it before manually checking messaging. Open the admin portal once to initialize the existing employee directory. The Auth-context event API follows the [Firebase Firestore trigger documentation](https://firebase.google.com/docs/functions/firestore-events).
